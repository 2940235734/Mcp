# Mcp
一款无需公网射影的MCP插件导入vscode绑定工作区即可便捷使用
Arena AI mcp
独立开发的 VS Code 扩展，将当前工作区连接到自建 PHP MCP 服务。默认地址：https://mcp.j0a.cn。

使用
在 VS Code 安装 VSIX，打开可信文件工作区，选择侧栏 工作区 MCP。
点击 绑定并连接工作区，插件会直接创建当前工作区的独立连接凭据。
点击 复制接入配置与提示词，把 JSON 部分填入支持 Streamable HTTP 的 MCP 客户端。
插件只记录自己发放的凭据，使用 VS Code SecretStorage 保存。不会读取、替换或修改其他扩展的账号、文件和配置。

按工作区随机生成（1.1.0）
首次选择并绑定一个工作区：后端安全随机生成 w_... 绑定 ID 与独立访问凭据，不使用项目名称/路径推算公开 ID。
同一工作区重开、重连、多窗口：复用已保存的随机绑定，不让已配置的 MCP 链接失效。
同名但目录不同：分别生成，互不共享绑定或文件访问范围。
点击 重新随机生成 或对应命令：选择目标工作区，确认后更换 ID 与凭据；旧链接和该工作区其他窗口的连接失效，需重新复制配置。
升级时兼容已存在的 1.0 版绑定；如需把已有 ID 换成新随机 ID，使用“重新随机生成”。
无需为每个工作区手工发放访问凭据，也无需服务器级绑定密钥。每个用户/工作区绑定后会自动得到独立的 Bridge/MCP 凭据；工作区接口仍要求 Bearer 认证。

1.1.1：选择项目与连接诊断
选择/更换项目：列出当前工作区根目录，显示完整目录以区分同名项目；也可通过 VS Code 的原生“添加文件夹到工作区”选择其他目录。切换只断开本窗口旧连接，保留各项目独立的缓存绑定。
诊断连接：在扩展宿主内测试健康接口及匿名绑定路由，不发送凭据，不访问项目文件。输出 Cloudflare 质询、DNS、TLS、超时及 HTTP 错误码，不再只显示 fetch failed。
首次绑定前禁用“重新随机生成”；请使用蓝色 为所选工作区随机生成并连接 按钮。
公网主页 status=ok 只说明浏览器这条链路成功；Cloudflare 等浏览器质询需要对 MCP/API 入口排除，插件不会自动完成网页质询或降低 TLS 校验。
1.2.1：Streamable HTTP 握手与在线状态
复制的 MCP 提示词要求支持 MCP 的客户端直接使用 Streamable HTTP；无法原生连接时通过 HTTP POST 完成 initialize、notifications/initialized、tools/list 握手。连接后遵循服务器 instructions，调用 workspace_status 确认项目在线并汇报，然后待命。

1.2.0：工作区文件权限默认开启
默认启用工作区文件新建、修改、删除和移动。工具调用直接执行，不弹出 VS Code 确认窗口；后端只做认证和任务转发，不保存工作区文件，也不增加二次确认。

权限范围为当前选择的工作区根目录。工作区信任、路径边界、符号链接、典型凭据文件和文本大小限制仍然有效，不执行任意终端命令。

工具
workspace_info：名称与访问权限。
workspace_status：确认项目在线并返回当前权限。
list_files：有限深度目录浏览。
read_file：按行读取 UTF-8 文本。
search_files：普通文本搜索。
get_diagnostics：读取编辑器已产生的诊断。
write_file：新建或覆盖工作区内文本文件；设置 j0aMcp.enableWrites 后显示，直接执行。
create_file：仅新建文本文件，目标存在时失败。
delete_file：删除工作区内普通文件，不删除目录。
move_file：在工作区内移动普通文件，不覆盖目标。
run_command：仅执行 j0aMcp.allowedCommands 中预先配置的固定命令 ID；默认关闭，不支持任意 shell 或提权。
默认启用文件修改。访问限于所选根目录，拒绝路径穿越、符号链接和典型凭据文件；忽略 .git、依赖目录、构建目录和后端 storage。文本大小上限 128 KiB。命令执行需单独开启并配置白名单，面板可关闭文件修改或命令执行。

默认链接不含令牌，客户端使用 Authorization: Bearer ...。管理员可开启 URL 令牌模式；完整链接属于凭据，应保持私密。复制配置会将凭据写入剪贴板，使用后可清空剪贴板。

断开连接只关闭本窗口桥接，不等同于撤销服务端凭据；永久撤销需使用 PHP 管理 CLI。多窗口共享绑定，但各自持有任务领取租约。

兼容范围
VS Code 1.96+，本地文件或远程扩展主机上的 file: 工作区。不支持虚拟文件系统。后端为 MCP JSON 模式的 Streamable HTTP，不是旧式独立 /sse 服务；只支持旧 SSE 的客户端需要升级。
